## Change Summary

**Simplified the canvas border color system from 7 states to 3 universal states.**

### V4.1 (Old) — 7-State Priority Cascade
1. Death flash (red, 500ms)
2. Phone ring (gold)
3. Phone pickup (green)
4. **Combo (dynamic: purple/blue/red/green)**
5. Reverse Controls (orange)
6. Invincibility (yellow)
7. Default (purple `#9D4EDD`)

### V4.2 (New) — 3-State Universal System
1. **Wall-phase effect** (purple `#800080`) — Safe to cross walls
2. **Invincibility effect** (yellow `#FFFF00`) — Protected state
3. **Default** (black `#000000`) — Walls are dangerous

---

## Rationale

### Problem
- **Visual confusion:** Combo mode showed red/purple/blue/green borders that looked like effects but weren't
- **Inconsistent semantics:** Phone call borders (gold/green) communicated temporary state, not danger level
- **Mode-specific rules:** Different border meanings in combo vs normal mode violated universal design principle
- **Cognitive overhead:** Players had to remember 7 different border meanings

### Solution
**Universal semantic borders:**
- ⚫ **Black = danger** (walls kill, default state)
- 🟣 **Purple = safe walls** (wall-phase effect active, can cross safely)
- 🟡 **Yellow = protected** (invincibility effect active, immune to death)

**Key insight:** Border color should communicate **immediate danger state**, not game mode or score progression.

---

## Design Principles

### 1. Universal Across Game Modes
Same rules apply in:
- Normal gameplay
- Combo Mode (no more special combo borders)
- Phone calls (no more gold/green borders)
- All effects (wall-phase and invincibility only affect borders)

### 2. Semantic Clarity
- **Black:** Walls are lethal (baseline danger)
- **Purple:** Walls are safe (wall-phase removes wall danger)
- **Yellow:** Snake is protected (invincibility removes all danger)

### 3. Effect-Based, Not Event-Based
- Borders reflect **active effects** (wall-phase, invincibility)
- NOT game events (phone calls, combo activation, reverse controls)
- Effects have duration and clear visual feedback

### Priority Cascade (V4.2)
```javascript
1. Wall-phase (purple)      // Highest priority if active
2. Invincibility (yellow)   // 2nd priority if active
3. Default (black)          // Fallback (always)
```

**Simple rule:** If no effects active → black. If effect active → effect color.

## Implementation Details

### Code Location
**File:** `js/game.js`
**Function:** `updateBorderState(gameState)`
**Lines:** 122-164

### V4.2 Implementation
```javascript
/**
 * Update canvas border color based on simplified universal rules (V4.2)
 * Event-driven: called ONLY when game state changes (effects applied/cleared)
 *
 * SIMPLIFIED BORDER RULES (applies to ALL game modes):
 * 1. Wall Phase (purple) - safe to cross walls
 * 2. Invincibility (yellow blinking) - protected state
 * 3. Default (black) - walls are dangerous
 */
export function updateBorderState(gameState) {
  const canvas = document.getElementById('game-canvas');

  // Clear all border classes first
  canvas.classList.remove(
    'border-phone-ring',
    'border-phone-pickup',
    'border-combo',
    'border-invincibility',
    'border-wallPhase'
  );

  // Simplified priority cascade

  // 1. Wall Phase (purple - safe to cross walls)
  if (gameState.activeEffect?.type === 'wallPhase') {
    canvas.classList.add('border-wallPhase');
    return;
  }

  // 2. Invincibility (yellow blinking)
  if (gameState.activeEffect?.type === 'invincibility') {
    canvas.classList.add('border-invincibility');
    return;
  }

  // 3. Default (black) - clear inline style, let CSS default take over
  canvas.style.borderColor = '';
}
```

### CSS Classes (Unchanged)
```css
/* css/style.css */

#game-canvas {
  border: 8px solid #000000;  /* Default black */
}

#game-canvas.border-wallPhase {
  border-color: #800080;  /* Purple - safe to cross walls */
  box-shadow: 0 0 20px 4px rgba(128, 0, 128, 1);
}

#game-canvas.border-invincibility {
  border-color: #FFFF00;  /* Yellow - protected */
  animation: borderBlink 400ms steps(2) infinite;
  box-shadow: 0 0 20px 4px rgba(255, 255, 0, 1);
}
```

## Impact on Game Systems

### Combo Mode
**Before V4.2:**
- Border changed to random color (purple/blue/red/green) when combo activated
- Created visual confusion: "Is purple a wall-phase effect or combo mode?"

**After V4.2:**
- Border stays **black** during combo mode (walls still dangerous)
- Border turns **purple** if player eats wall-phase food during combo
- Border turns **yellow** if player eats invincibility food during combo
- Combo mode has NO unique border color

### Phone Calls
**Before V4.2:**
- Border turned **gold** when phone rang
- Border turned **green** during pickup timer
- Communicated "decision point" and "commitment" states

**After V4.2:**
- Phone calls have NO border effect
- Border stays consistent with effect state (black/purple/yellow)
- Phone state still visible via overlay and UI elements

### Food Effects
**Before V4.2:**
- Wall-phase: purple border ✅
- Invincibility: yellow border ✅
- Reverse Controls: orange border (planned, never implemented)

**After V4.2:**
- Wall-phase: purple border ✅ (kept)
- Invincibility: yellow blinking border ✅ (kept)
- Reverse Controls: NO border effect (removed)

**Before V4.2:**
- "Border is gold... is that a phone call or an effect?"
- "Border is purple... combo mode or wall-phase?"
- **7 different border meanings to remember**

**After V4.2:**
- "Border is black → walls dangerous"

- **3 meanings, all danger-related**

### Consistency Across Modes
**Before V4.2:**
- Normal mode: purple default, effect colors override
- Combo mode: dynamic combo color overrides everything
- Phone calls: gold/green override effects
- **Different rules per mode**

**After V4.2:**
- All modes: black default, effects (purple/yellow) override
- **Same rules everywhere**
